fn-7 One-time setup privilege and helper resilience

Approve sudo once at setup. After that, list edits and the site block never ask again. The helper also stays up when a network job, window event, or notification fails.

fn-4 product behavior stays. This spec is hardening plus a single privileged install path — not a rewrite of the list, banner, or expand map.

02

Architecture

scope: technical
One setup
A single privileged install asks for sudo once and writes the constrained helper plus its grant.
Unprivileged runtime
Reload, placement, and site-block apply/lift call the already-installed helper with no new prompt.
Stay up
Worker and listener isolate job/event failures. Reloads serialize. Notify never kills the loop.
03

Boundaries

scope: business
Is
  • One-time setup sudo
  • No runtime sudo prompt after setup
  • Worker, listener, reload, and notify resilience
Is not
  • Re-open fn-4 list membership, banner copy, or expand map
  • Required helper-module split or shared test-fixture extraction
  • A second interactive uninstall product flow
04

Decision

scope: both
Privilege UX
One setup sudo. Runtime keeps the constrained helper so day-to-day use never asks again.

“allow sudo one time only during setup only and not for every single thing that has to happen one by one”

Rejected: prompting sudo on every apply or install file.
Hardening vs rewrite
Quality findings stay in the existing helper. Module split is out of scope for close.
